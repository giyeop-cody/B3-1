# B3-1 동료평가 시나리오

## 1. 학습
- 해시 함수 (문자열→숫자 변환, 모듈러 연산)
- 충돌 해결 (체이닝, 개방주소법)
- 시간 복잡도 (O(1) vs O(n))
- 캐싱 (LRU)

## 2. 고찰
- "dict가 어떻게 O(1)을 달성하는지" — 해시 함수 + 배열
- "충돌은 피할 수 없지만 관리할 수 있다"

## 3. 시도
- 해시 함수: ord 합산 + 모듈러
- put/get 연산 구현
- 체이닝으로 충돌 해결
- LRU 캐싱

## 4. 수정
- 단순 합산 → 곱셈 혼합 (분산성 개선)
- 테이블 크기: 10 → 100 (충돌 감소)

## 5. 선택과 선정
- 체이닝 vs 개방주소법: 체이닝 (구현 단순, 메모리 유연)
- 해시 함수: 단순 합산 vs 곱셈 혼합 — 분산성 고려

## 6. 트러블슈팅
- 충돌 많음 → 테이블 크기 증가 + 해시 함수 개선
- O(1)이 아닌 경우 → 충돌 시 체이닝 탐색 O(n) 발생

## 7. 평가 예상 질문
- 해시 함수 설계? → 분산성/결정성
- 충돌 해결? → 체이닝 vs 개방주소법
- O(1) 조건? → 잘 분산 + 충분한 크기
